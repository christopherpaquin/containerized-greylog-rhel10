# Worklog

## 2026-08-11 15:49
**Task:** Build a production-quality one-click Graylog deployment for RHEL 10 using Podman + systemd Quadlets (SELinux Enforcing), per detailed spec: dedicated network, bind mounts w/ correct SELinux labels, generated+persisted secrets, idempotent deploy.sh/healthcheck.sh/uninstall.sh, BATS unit+integration tests, README+docs.
**Decision:** Pinned Graylog 7.1.7 / Data Node 7.1.7 / MongoDB 8.2.12 (validated against Graylog's official compatibility matrix). Used Graylog's built-in `GRAYLOG_SELFSIGNED_STARTUP` for Data Node TLS (auto self-signed CA, no manual preflight) instead of hand-rolling certs, then set the renewal policy to a 10-year lifetime via `PUT /api/system/cluster_config/org.graylog2.plugin.certificates.RenewalPolicy` (discovered by querying the live instance's cluster_config class list - not documented). Enabled MongoDB auth. Provisioned a dedicated `graylog-stack-automation` Admin user for API tokens, since Graylog's built-in root user has no real MongoDB ObjectId and can't own tokens. Secrets delivered via Podman `Secret=` (not plaintext Environment=), created once and never rotated on reruns. Quadlet templates rendered from `quadlet/*.tmpl`-style sources via envsubst in deploy.sh, with per-unit changed-detection so reruns only `systemctl restart` units whose rendered content actually changed (plain `start` is a no-op on an already-active unit and would silently skip picking up changes).
**Why:** All decisions here were validated empirically against a real RHEL 10.2 VM (10.1.10.64, user-provisioned, not raptor.lab) rather than guessed - the task explicitly required live testing before declaring done, and several critical facts (Data Node health endpoint switches HTTP->HTTPS-only after provisioning; MongoDB/Data Node entrypoints need CHOWN/DAC_OVERRIDE/FOWNER/SETUID/SETGID even briefly as root under DropCapability=ALL; Graylog's bundled JRE has a cap_net_bind_service file capability that trips NoNewPrivileges without AddCapability=NET_BIND_SERVICE even though no privileged port is used; Podman's bridge interface has no firewalld zone by default and silently breaks aardvark-dns after any firewalld reload) were only discoverable by deploying for real and reading actual logs/errors - documentation and training-data assumptions were wrong or silent on all of them.
**Progress:** Done and fully validated. 60/60 unit tests (BATS, run locally, no root) and 43/43 integration tests (BATS, run as root on the live VM: 19 deployed-system checks, 11 idempotency-sequence checks, 13 deploy->uninstall->deploy roundtrip checks) all pass. Live-verified: fresh deploy -> HEALTHY (incl. real end-to-end syslog TCP+UDP ingestion via logger + Graylog search API), idempotent rerun (no secret rotation/duplicates/restarts), uninstall (data-preserving) -> redeploy (same credentials/data), uninstall --purge-data -> clean host, mongodb service kill -> full stack self-heals via systemd Restart=on-failure. SELinux Enforcing throughout, exactly 3 ports exposed (9000/tcp, 1514/tcp, 1514/udp), no chmod 777 / setenforce 0 anywhere. README + docs/ (architecture, selinux, troubleshooting, syslog-forwarding, backup, sizing) reflect the actual implementation including the firewalld/DNS bug found and fixed.
